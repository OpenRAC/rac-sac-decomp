# STARTING PROMPT — Ratchet & Clank: Secret Agent Clank

> This file is the **starting prompt** of the project. It is intended to be
> pasted as-is into an agent, or read by an agent starting a work session.
> The rest of the repository refers to it.

---

## 1. Project identity

You are working on the byte-for-byte matching decompilation project of
**Ratchet & Clank: Secret Agent Clank**. The objective is to reconstruct the
retail program in **compiled C/C++**, with proof: the byte produced by
the compiler must be **identical** to the retail byte, at every applicable
placement, and the complete program must rebuild.

This repository is a **starting point**: the method, rules, templates, and
tooling are in place; the local target (game image, hash table, toolchain)
must be pinned before any campaign.

## 2. What to read before acting

1. `README.md` — the project, the method, the legal boundary.
2. `AGENTS.md` — the ten working rules, non-negotiable.
3. `docs/METHOD.md` — the wave protocol, end to end.
4. `docs/EVIDENCE.md` — what counts as evidence, and what does not.
5. `docs/STATE.md` — the anchor of the project: current status, what to do next.
6. `docs/REUSE.md` — what we borrow from sibling projects (RAC1, RAC2, RAC5).
7. `docs/VERSIONS.md` — the releases of the game (USA and Europe), how they are tracked and checked.

## 3. Hard rules (summary; `AGENTS.md` is authoritative)

1. **Never write to `master`/`main`.** Agent work lives in `work/<LOT>/`.
2. **Pure C**: no inline or global assembly, no `.word`, no fixed register
   bindings, no artificial barriers. C evidence must come from instructions
   **generated by the compiler**.
3. **No codegen steering.** No construct whose sole purpose is to alter
   register allocation is allowed. If the retail byte does not come out of the
   source, the source is not yet right: recover the **authentic form** of the
   routine.
4. **One boundary = one owner.** No overlapping bounds, no duplicate names.
   A compiled prefix is not a complete function.
5. **Explicit promotion.** C counts only when it is actually linked at every
   reviewed placement and the complete-program gates pass.
6. **Evidence-based profiles.** A compiler, an option, or a patch requires a
   measured cause, provenance, and regression controls.
7. **Proven names and types.** Reference symbols remain stable; an alias,
   prototype, field size, or signedness requires evidence (symbols, code,
   callers, or data).
8. **Bounded experiments.** After three attempts within the same mismatch
   class: park the best source with its first difference and a reopening
   condition.
9. **Original behavior.** Original bugs are preserved. Bug fixes or PC ports
   are a separate undertaking, earning no matching credit.
10. **Public hygiene.** No game bytes, instruction listings, proprietary
    toolchains, or personal paths in commits.

## 4. The workstation

| Element | Path | Role |
|---|---|---|
| Repository | this directory, `main` branch | public code: written source, tools, docs |
| Local target | `LOCAL.md` (git-ignored) | game image, hashes, toolchain |
| Workspace | `work/` (git-ignored, except templates) | extracted modules, bounds, lots, agent folders |
| Anchor | `docs/STATE.md` | project state, to be read and updated |

`work/` is **private by design**: `.gitignore` excludes content extracted from
the game, raw reports, and intermediate results. Only what is authored and
reusable lives in the repository.

## 5. How to start a wave

The complete protocol is in `docs/METHOD.md`. In summary:

1. **Foundation (E0)** — an agent extracts the local target, computes hashes,
   and produces the **shortlist** of bounded candidates: a table of
   `module, offset, size, boundary source, raw body sha, shared placement count`.
2. **Lots** — the shortlist is partitioned into lots (`work/lots/L*.tsv`). One
   lot = one folder `work/<LOT>/` and **a single agent**.
3. **Translation** — each agent writes one C source per target, in
   `work/<LOT>/bodies/`, and proves it with the harness. **`*** EXACT ***` is the
   only proof.** Otherwise: first difference and profile attempted.
4. **Integration (root)** — root recompiles, places each body at every one of
   its placements, requires the complete-program digest, regenerates catalogues
   and progress, runs tests, then commits.
5. **Resumption** — `docs/STATE.md` and `work/*/RAPPORT.md` always state what to
   do next.

```
You are an agent in wave <N> of the <name> campaign for the
Ratchet & Clank: Secret Agent Clank decompilation.

READ IN FULL FIRST, in this order:
  1. AGENTS.md
  2. docs/METHOD.md
  3. docs/EVIDENCE.md
  4. docs/STATE.md
  5. docs/REUSE.md
  6. docs/VERSIONS.md

YOUR LOT: <LOT>
YOUR LIST: work/lots/<LOT>.tsv
YOUR FOLDER: work/<LOT>/   -> write ONLY there (bodies/, abandonnes/, work/, RAPPORT.md)

MANDATE: translate the retail function bodies in your list into pure C. One
file per target: work/<LOT>/bodies/<MODULE>_<OFFSET>.c. Each body must be
PROVEN by the harness: proof is the byte-for-byte comparison between the
compiled body and the retail bytes at the target placement. Nothing else counts.

METHOD: read the retail disassembly of the target, reconstruct the C (types,
boundaries, calls, global data), write the body, test, correct. If the byte
does not match, do not steer the compiler: seek the AUTHENTIC FORM of the
routine in the references listed in docs/REUSE.md and docs/STATE.md, and replay
the original structure (where values live, how many are live at once, in what
order they are produced).

RULES: NEVER write to the repository outside your lot folder; pure C (no asm,
no .word, no fixed registers); never run global gates or a full build (root
integrates); after three attempts of the same mismatch class, park the body in
abandonnes/ with the first difference and a reopening condition; promise only
what the harness printed.

DELIVERABLES: bodies/*.c (+ .map if local data needs fixing), resultats.tsv,
abandonnes/ if needed, and RAPPORT.md in English (20 lines maximum): number of
exacts, list of module:offset size profile, notable near-matches, blockers,
leads.

Autonomous work to the end: do not ask questions, make decisions, and conclude
with the final report.
```

## 7. Publication rules

Nothing from the following list must ever enter the repository, even "temporarily":

- disc image, retail binary, extracted modules;
- retail bytes, instruction listings, disassemblies;
- raw harness reports, compilation logs;
- SDK source, proprietary headers, leaked code;
- secrets, personal paths, credentials.

What is public: hand-**authored** sources, reusable tools (with their tests),
research metadata (names, addresses, hashes), and method documentation.
